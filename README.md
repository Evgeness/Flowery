# Flowery

Веб-приложение для помощи в уходе за растениями.

## О проекте

Flowery помогает пользователю отслеживать свои растения, получать информацию об уходе, Уведомления о поливе приходят через Telegram-бота.

## Возможности

- Регистрация и авторизация пользователей
- Главный экран со списком отслеживаемых растений
- Добавление растения из базы
- Просмотр информации о растении и советов по уходу
- Уведомления о поливе через Telegram
- Подтверждение полива в Telegram-боте

## Frontend

### Стек технологий
- **React** — основа для построения пользовательского интерфейса.
- **TypeScript** — статическая типизация для надежности и предотвращения ошибок.
- **Vite** — сверхбыстрый сборщик и сервер разработки.
- **React Router DOM** — клиентская маршрутизация (SPA).
- **Material-UI (MUI)** — библиотека UI-компонентов для создания современного и доступного интерфейса.

### Дизайн и стилизация
Приложение выполнено в эко-стиле с использованием нежно-зеленой палитры:
- **Кастомная тема MUI**: Настроены глобальные шрифты, палитра цветов и скругления углов (border-radius) для всех компонентов.
- **Кастомные шрифты**: Для логотипа используется рукописный шрифт *Caveat*, для основного текста — системные шрифты и *Roboto*.
- **Фоновые паттерны**: На главном фоне реализован кастомный бесшовный SVG-паттерн с листьями.
- **UI-элементы**: Кнопки имеют градиентную заливку и адаптивные hover-эффекты. Для навигации реализована плавная смена состояний (активная/неактивная кнопка).
- **Адаптивность (Responsive Design)**: Интерфейс корректно отображается на мобильных устройствах, планшетах и ПК (сетки карточек автоматически перестраиваются).

### Архитектура
- **Persistent Layout**: Реализован общий макет (Layout) с постоянным боковым меню (Drawer), которое не перезагружается при переходе между экранами. Контентная часть меняется динамически с помощью `<Outlet />`.
- **Компонентный подход**: Интерфейс разбит на переиспользуемые компоненты (`AuthLayout`, `Layout` и отдельные страницы).

### Экраны приложения
- **Описание проекта (Welcome)** — стартовый экран с презентацией приложения.
- **Авторизация** — форма входа.
- **Регистрация** — форма создания аккаунта.
- **Главный экран (Dashboard)** — список текущих растений пользователя (или заглушка с призывом добавить первое растение).
- **Выбор растения** — каталог доступных растений с модальным окном для просмотра описания перед добавлением.
- **Экран растения** — детальная информация о конкретном растении, график полива и уход (в разработке).


## Backend

### Стек технологий
- **Python 3.12+** — язык программирования серверной части.
- **FastAPI** — современный асинхронный веб-фреймворк для создания быстрого API.
- **PostgreSQL** — надежная реляционная база данных.
- **SQLAlchemy 2.0 (Async)** — асинхронная ORM для работы с базой данных.
- **Alembic** — инструмент для миграций базы данных.
- **Pydantic v2** — библиотека для валидации входящих и исходящих данных.
- **Passlib / JWT** — библиотеки для безопасного хеширования паролей и работы с токенами авторизации.

### Архитектура и безопасность
Проект построен по принципам чистой архитектуры с разделением ответственности:
- **Слоистая структура**: Код разделен на маршруты (`api/routes`), бизнес-логику (`crud`), модели БД (`models`) и схемы валидации (`schemas`).
- **Асинхронность**: Все операции с базой данных выполняются асинхронно (`async/await`), что обеспечивает высокую производительность.
- **Безопасность**: Пароли хранятся в виде стойких хешей (bcrypt). Реализована двухфакторная JWT-аутентификация (Access + Refresh токены).
- **Ролевая модель**: Четкое разделение прав доступа (Обычный пользователь / Администратор).
- **Telegram-интеграция**: Каждому пользователю при регистрации присваивается уникальный `UUID`, который используется для привязки аккаунта к Telegram-боту.

### База данных и модели
Система состоит из связанных сущностей, покрывающих все потребности приложения:
- **Пользователи (Users)**: Хранит данные для входа, роль (user/admin), UUID и привязанный Telegram ID.
- **Каталог растений (Plants)**: Справочник всех доступных растений, содержащий описание и базовый интервал полива (в днях). Редактируется только администраторами.
- **Растения пользователя (UserPlants)**: Промежуточная таблица, связывающая пользователя с конкретным растением. Позволяет давать растению кастомное имя (например, "Моя Монстера").
- **Отслеживание состояния (Tracking)**: Для каждого экземпляра растения пользователя хранится дата последнего полива (`last_watered_at`) и автоматически рассчитывается дата следующего (`next_watering_at`).

### API (Маршруты)
- **`/api/auth`** — Регистрация, вход (выдача JWT токенов), обновление токена (refresh) и выход.
- **`/api/plants`** — Получение общего каталога (публично) и CRUD-операции для администраторов.
- **`/api/my-plants`** — Добавление растения из каталога в свой список, просмотр своих растений и их удаление.
- **`/api/my-plants/{id}/water`** — Специальный эндпоинт для отметки полива, который автоматически пересчитывает следующую дату полива на основе интервала растения.

## Telegram-бот

- Уведомления о поливе
- Подтверждение полива по кнопке
- Отслеживание полива растений
- Регистрация через ID и пароль
